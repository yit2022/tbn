This document describes how to prepare a machine to work on this repository. It is the installation guide for the repository that exists today: a GitHub profile README, with no application runtime.

1. Purpose and scope

This guide defines the device set used to read, edit, and verify github.com/yit2022/yit2022, and it gives the exact installation procedure for that set. Follow it when setting up a workstation or when confirming that a Cursor Cloud Agent environment can check the repository out and leave it ready to edit.

The repository contains one tracked file, README.md. That file is the GitHub profile page for @yit2022. It states an interest in robotic process automation and UiPath. The repository does not contain a UiPath project, a package manifest, a Dockerfile, tests, or a server. Installation therefore does not download packages and does not start a process.

1.1 What this guide covers

  • The two devices in the set, and which one you need.
  • Required software, with the versions observed on the validation virtual machine.
  • Software that is present on the Cloud Agent image and is not used by this repository.
  • The install command, how to run it twice, and the acceptance check.
  • Failures that look like environment problems and are actually a wrong working directory.

1.2 What this guide does not cover

  • Installing UiPath Studio, Robot, or Orchestrator. Nothing in this repository calls those products.
  • Publishing the profile, GitHub account settings, or DNS.
  • Production deployment. There is no deployed service.

1.3 How to read the tables

Device and software rows use stable identifiers (DS-WS, SW-GIT). “Required” means the installation in this guide fails or cannot be verified without that item. “Image only” means the tool was present on the validated Cloud Agent virtual machine and is not invoked by the install or the acceptance check.

2.1 Workstation requirements (DS-WS)

Any current desktop or laptop is sufficient. The procedure was not tied to a CPU count or a memory size. Provide:

  • An operating system that can run Git and Bash, or Git Bash on Windows.
  • Git 2.30 or newer. The validation machine used Git 2.43.0.
  • Python 3.9 or newer, used only by the acceptance check in section 6. The install command itself is shell.
  • A text editor. No IDE is required.
  • Network access to github.com for the initial clone.

Disk use after clone is a few kilobytes for the Git history plus the 434-byte README. Reserve a normal working copy; there is no build output.

3.3 Secrets and network

No API token, password, or private registry is required to install or verify this repository. Cloning over HTTPS uses whatever GitHub authentication the operator already has. The install command makes no outbound request. A machine that cannot reach the public internet can still run install and verification on an existing checkout.

5. Installation

Installation is intentionally small. It proves the checkout is the repository root and then exits. It does not modify files, install packages, or listen on a port. Running it again is the idempotence check: the second run must also exit 0 and print the same line.

5.1 Install command

Save this as the Cloud Agent install command, or run it from the repository root in any Bourne-compatible login shell. Keep the three lines. Do not join them with &&.

set -euo pipefail
test -f README.md
echo "No package dependencies. Profile README repository is ready."

Expected standard output, and nothing on standard error:

No package dependencies. Profile README repository is ready.

Exit status 0. If README.md is absent, test returns status 1 and set -e stops the script before the echo.

5.2 Install on a workstation (DS-WS)

  1. Install Git and Python 3

    Use section 3.1. Skip this step when git --version and python3 --version already succeed.

  2. Clone the repository

    Pick an empty parent directory. The clone creates yit2022.

    git clone https://github.com/yit2022/yit2022.git
cd yit2022
git status
git rev-parse --abbrev-ref HEAD

    git status should report a clean work tree. The branch should be main unless you checked out another branch on purpose.

  3. Run the install command

    From the clone root:

    bash -lc 'set -euo pipefail
test -f README.md
echo "No package dependencies. Profile README repository is ready."'

  4. Run it a second time

    Repeat the same command. A second success is the idempotence evidence. The script creates no cache, lock, or virtual environment, so the second run cannot drift from the first.

  5. Run the acceptance check

    Continue with section 6 before treating the machine as ready.

5.3 Install on a Cloud Agent (DS-CA)

Cursor checks the repository out into /workspace and then runs the install command from that directory. Put only the three lines from section 5.1 in the environment install field. Leave the start field empty.

Why there is no start command. Start is for processes that must keep running, such as a database or a development server. This repository has neither. An empty start field means no per-boot process is launched for the project. Do not put the install command in start, and do not put a server in install.

  1. Confirm the workspace

    pwd prints /workspace. ls README.md prints README.md. If the file is missing, stop. Do not create a substitute README to force install to pass.

  2. Run install the way the environment runs it

    bash -lc 'set -euo pipefail
test -f README.md
echo "No package dependencies. Profile README repository is ready."'

  3. Repeat the command

    The second exit status must be 0. On 5 October 2026 both runs printed the ready line and exited 0.

  4. Do not start a server

    There is no port to open. Readiness is the acceptance check in section 6, not an HTTP response.

6. Verification

Run this from the repository root after install. It is the acceptance check for both devices. Python’s standard library is enough; do not pip install anything for it.

python3 - <<'PY'
from pathlib import Path
text = Path("README.md").read_text(encoding="utf-8")
visible = []
for line in text.splitlines():
    stripped = line.strip()
    if not stripped or stripped.startswith("<!") or stripped.startswith("yit2022/") or stripped.startswith("You can click") or stripped.startswith("--->"):
        continue
    visible.append(stripped)
if "```" in text and text.count("```") % 2 != 0:
    raise SystemExit("unbalanced markdown fences")
required = ["yit2022", "UIPATH", "rofric2020@gmail.com"]
missing = [item for item in required if item not in text]
if missing:
    raise SystemExit(f"profile content missing: {missing}")
if len(visible) < 4:
    raise SystemExit("profile README has too few visible lines")
print(f"bytes={len(text.encode())} lines={len(text.splitlines())} visible_lines={len(visible)}")
print("--- visible profile ---")
print("\n".join(visible))
print("HELLO_WORLD_OK")
PY

On the validated README the check printed:

bytes=434 lines=10 visible_lines=5
--- visible profile ---
- 👋 Hi, I’m @yit2022
- 👀 I’m interested in Robotic Process automation
- 🌱 I’m currently learning UIPATH
- 💞️ I’m looking to collaborate on robotic process automations projects
- 📫 How to reach me rofric2020@gmail.com
HELLO_WORLD_OK
Byte count. bytes=434 and lines=10 describe the README before this guide was added. After any edit to README.md, those two numbers change. HELLO_WORLD_OK is the pass signal. A missing required string, fewer than four visible lines, or an unbalanced fence is a failure.

7.2 Editing the profile

  1. Edit README.md on a branch

    Keep the profile readable as a short list. The HTML comment block at the bottom is a GitHub profile hint; leaving it in place does not affect the visible page.

  2. Re-run section 6

    If you rename the GitHub login, change the learning line so it no longer contains UIPATH, or replace the contact address, update the required list in the acceptance check in the same change.

  3. Re-run install

    Install still only checks that the file exists. Run it once after the edit to confirm the working directory is still the root.

7.3 Reprinting this PDF

Edit docs/device-set-and-installation-guide.html, then from the repository root:

bash scripts/render-device-guide.sh

The script needs Google Chrome on PATH. It writes docs/device-set-and-installation-guide.pdf next to the HTML. Commit the HTML and the PDF together so the printed guide matches the source.

8. Troubleshooting

SymptomLikely causeWhat to do
Install exits 1 with no ready line README.md is not in the current directory. Run pwd and ls. cd to the clone root, or to /workspace on a Cloud Agent, and run install again.
bash: set: pipefail or set: -u is rejected The script was executed by sh, not Bash. Run it with bash -lc, as in section 5.2.
Ready line prints, then git status shows modifications Something other than this install command changed files. The install command does not write. Inspect git diff. Do not attribute those edits to install.
Acceptance check prints profile content missing The README no longer contains one of the three required strings. Restore the string or update the check and this guide together.
python3: command not found Python 3 is not installed. Install can still succeed, because it is shell-only. Install Python 3 (section 3.1) and re-run section 6. Do not mark the device ready on the install line alone.
Clone asks for credentials or returns 403 GitHub authentication for a private fetch, or no network path to github.com. This repository’s public README clone does not need a token. Confirm the URL is https://github.com/yit2022/yit2022.git and that HTTPS to github.com works.
node -v and npm -v disagree about the major install Known image layout in Table 4. Two Node installs are on the machine. Ignore it for this repository. If you add Node later, select one prefix deliberately.
A port is already in use during setup Another project’s server. This guide starts none. Do not add a server to make this repository “look” ready. Readiness is HELLO_WORLD_OK.
